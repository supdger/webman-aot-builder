## Why

Laravel 13 的 Illuminate 时间间隔源码变化会触发固定文本兼容规则的零次匹配；Windows 构建还可能在项目镜像目录激活时失败且缺少底层原因。需要让已知等价写法能够构建，并让瞬时文件占用可恢复而不削弱源码与产物安全边界。

## What Changes

- 对 Illuminate 时间间隔调用按源码结构识别旧、新及已适配写法，保持语义和重复构建安全。
- 核查同一时间间隔规则组的固定文本断言，仅修复本次确认的同类兼容缺口。
- 对 Webman/Workerman 已确认等价源码形态采用结构优先验证，兼容新版本与写法变化。
- 为 Windows 镜像目录激活增加有限恢复与原始原因诊断，保留目标冲突、源码漂移和隔离检查。
- 业务依赖仅可采用已验证版本下限，不预设上限或用精确版本白名单拒绝较新版本；未知版本标签给出有依据的结构检查或诊断。
- 用直接相关回归及实际可执行的平台构建验证结果，明确源码测试与发布包验证的区别。

## Capabilities

### New Capabilities

- `build-source-compatibility`: Illuminate 时间间隔写法兼容及异常结构安全停止。
- `build-mirror-recovery`: 项目镜像激活的有限恢复、失败诊断和隔离安全。

### Modified Capabilities

无。

## Impact

影响锁定生成器的本仓兼容 overlay、ProjectMirror、相关测试与受影响兼容说明。基于 0.4.0 源码；用户后续明确授权提交发布，发行目标为 0.4.1，通过 feature branch / PR 合并、tag 与 Release 资产交付，不直接推送 main，不同步用户宿主或执行数据库操作。Wiki 保留草稿，未授权推送。原项目和 vendor 不被改写，临时材料保存于仓库外。

## 0.4.1 后补修

用户要求“把所有的版本锁定都改成兼容”。实际 Workerman 5.2.3 被生成器历史源码摘要拒绝，captcha 仍有 version/reference 门禁。接续原变更，覆盖生成器、后置适配、覆盖规划、运行资源及可选适配的全部项目依赖锁点，以实际源码/资源结构及本次输入输出摘要替代历史精确准入。固定生成器、SDK 与发行材料锁保持完整性；既有最低版本仅保留有依据的下限，不承诺任意未来版本可用。本次源码与回归授权不推导新的提交、发布或用户宿主操作授权。

## 用户再次纠正：所有准入按能力处理

用户原话：“那你还不赶紧解决？不允许有上限，必须做兼容性处理，不允许有锁定版本的情况！！！！”。完整有效生成器审计仍发现大量精确文本与历史次数门禁，已证实 JWT、brick/math、Illuminate Sleep、Guzzle MessageFormatter、Symfony MetadataBag 五个 token 等价注释输入被拒绝；此外 Carbon/ThinkORM 下限、Composer 插件 API ^2.0 上界，以及安装/构包/工具准备中的硬编码版本准入均需按本次要求继续处理。前轮 fresh5 成功仅证明初始 installed 快照，不能宣称本轮目标已完成。

本次将所有项目依赖、安装接口及适用编译材料的版本准入改为可观察能力、源码转换契约及 manifest 声明绑定：不设 semver 上限、精确版本白名单或历史下限拒绝。工具链可保留一个已验证默认组合，版本字段可标识实际材料；下载目标、补丁源码及材料摘要一致性继续校验，但适用版本由 manifest 和能力证明决定，不能硬编码旧版 exact gate 拒绝其他材料。无依据的旧总次数与格式限制须改为逐语义结构转换及完整覆盖检查。
